## Complete backup (D23)
- **Backup format 2**: `GET /api/export` now carries everything the person owns (profile, weights, check-ins, food log, saved meals, own foods, plans, workouts with sets, finisher data, plan links, records, XP, achievements, notifications, coach chats with safety category) plus `appVersion`/`mode`; the client adds a separate `clientSettings` block (whitelisted browser settings, no credentials). Never exported: passwords, sessions, replay records, quota counters, the hidden device username. Version 1 files still restore what they carry.
- **Restore** (`POST /api/device/restore`) REPLACES every section the file carries, in one transaction (all or nothing), set-based, rate limited, with records/XP/readiness recomputed or evidence-checked, minors' rules re-applied, chats re-checked by the safety shield, and a result summary (`restored` / `skipped` / `untouched`). Restoring the same file twice changes nothing. The Profile backup panel states what will be replaced, shows what came back in plain words (he + en), and gives specific errors (wrong file, damaged, too large, newer format). Details, residual risks and what is deliberately not restorable: `docs/DECISIONS.md` D23.
- **Proof**: `server/test/backup.test.ts`, client backup/clientSettings/Profile/deviceCore tests, and `e2e/device/f-profile-backup.spec.ts` (export -> delete all data -> onboarding -> restore in the real device build).
