# LUPU Study AI 🎓✨

פלטפורמת לימודים אישית מבוססת בינה מלאכותית לתלמידי חטיבת ביניים ותיכון (ברירת מחדל: כיתה ח׳).
מורה פרטי דיגיטלי שמסביר, בודק תשובות, מכין למבחנים, יוצר סיכומים וכרטיסיות, ועוקב אחרי ההתקדמות.

- **עברית מלאה ו-RTL**, מצב כהה/בהיר, רספונסיבי (טלפון, טאבלט, מחשב), PWA להתקנה.
- **Next.js 15 (App Router) + TypeScript**, Tailwind CSS, רכיבי UI בסגנון shadcn/ui, Lucide, Recharts, Zod.
- **Supabase** (אימות, מסד נתונים עם RLS, אחסון קבצים פרטי) · **Anthropic API** דרך השרת בלבד.
- עובד **מיד, בלי שום הגדרה**, במצב מקומי (הנתונים נשמרים במכשיר). פיצ׳רי ה-AI מופעלים כשמוסיפים מפתח.

> 📌 המסמך הזה כן ומדויק: בסעיפים [מה עובד בפועל](#-מה-עובד-בפועל) ו-[מה עוד דורש הגדרה או פיתוח](#-מה-עוד-דורש-הגדרה-או-פיתוח) מפורט בדיוק מה נבדק ומה לא.

## 🚀 התחלה מהירה

דרישות: Node.js 20 ומעלה.

```bash
cd lupu-study-ai
npm install
npm run dev          # http://localhost:3000
```

זהו. האפליקציה פועלת במצב מקומי: הקמה (Onboarding), דשבורד, מקצועות, שיעורי בית, מבחנים, כרטיסיות, לוח שנה, מצב ריכוז, התקדמות והישגים – הכול עובד בלי שרת ובלי מפתחות.
מורה ה-AI, צילום שאלות, סיכומים חכמים ויצירת שאלות/כרטיסיות באמצעות AI יציגו הודעה ברורה "לא מחובר" עד שתגדירו מפתח (ראה למטה). **לעולם לא מוצגות תשובות AI מדומות.**

רוצים להתרשם? בדשבורד לחצו **"טען נתוני דמו"** (מסומן בבירור בבאנר, ואפשר להסיר בלחיצה בהגדרות).

## 🔐 הגדרת משתני סביבה

```bash
cp .env.example .env.local
```

| משתנה | נדרש ל | הערות |
|---|---|---|
| `ANTHROPIC_API_KEY` | מורה AI, צילום שאלות, סיכומים, יצירת שאלות | **צד שרת בלבד.** לעולם לא עם `NEXT_PUBLIC_` |
| `ANTHROPIC_MODEL` | – | ברירת מחדל `claude-sonnet-5-5`. אפשר להחליף ללא שינוי קוד |
| `ANTHROPIC_BASE_URL` | – | אופציונלי (gateway/פרוקסי). ברירת מחדל `https://api.anthropic.com` |
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` | חשבונות וסנכרון | מפתח ה-anon ציבורי בכוונה; ההגנה על הנתונים היא RLS |
| `AI_RATE_LIMIT_PER_MINUTE` / `_PER_DAY` / `AI_GUEST_RATE_LIMIT_PER_DAY` | – | הגנה מפני ניצול לרעה ועלויות (ברירות מחדל: 12 / 150 / 15) |
| `AI_MAX_OUTPUT_TOKENS` | – | תקרת אורך תשובה (ברירת מחדל 1800) |

### חיבור Anthropic API
1. צרו מפתח ב-[console.anthropic.com](https://console.anthropic.com).
2. הוסיפו ל-`.env.local`: `ANTHROPIC_API_KEY=sk-ant-...`
3. הפעילו מחדש (`npm run dev`). בהגדרות → "מורה AI" יופיע "מחובר למודל".
4. לבדיקה: פתחו את מסך "מורה AI" ושאלו שאלה. התשובה מוזרמת בזמן אמת, עם נוסחאות LaTeX.

כל הקריאות עוברות דרך `src/services/ai/` – שכבה מרכזית עם ממשק `AiProvider`. כדי להחליף ספק/מודל כותבים מימוש חדש לממשק ובוחרים אותו ב-`getProvider()` (`src/services/ai/index.ts`), בלי לגעת בשאר האפליקציה.

### מודל חינמי / תואם OpenAI (למשל Big Pickle ב-OpenCode Zen)
אפשר להחליף את ספק ה-AI בלי לשנות קוד. ב-`.env.local`:
```
AI_PROVIDER=openai
AI_BASE_URL=https://opencode.ai/zen/v1
AI_MODEL=big-pickle
```
(מודלים נוספים: `curl https://opencode.ai/zen/v1/models`). עובד גם עם OpenRouter, Ollama ו-vLLM.
**לפני שמשתמשים, חשוב לדעת:**
- **פרטיות:** לפי התיעוד של OpenCode, בתקופת השימוש החינמי השיחות עשויות לשמש לשיפור המודל. האפליקציה מיועדת גם לקטינים, ולכן **לא מומלץ** לשלוח דרך מודל כזה שאלות של תלמידים אמיתיים.
- **מכסה:** בניסוי שלי (28.10) כל המודלים החינמיים החזירו `Free usage limit reached`, כי המכסה החינמית מיועדת לשימוש בתוך OpenCode ולא ל-API של אפליקציה. ייתכן שנדרש מפתח/מנוי.
- **תמונות:** מודלים טקסטואליים לא מקבלים תמונות. ברירת המחדל `AI_VISION=false` מושבתת בצילום שאלות ובצירוף תמונות; הגדירו `AI_VISION=true` רק למודל עם ראייה (למשל `nemotron-3.5-super-vl-free`).
- איכות העברית, ההקפדה על פלט JSON והתגיות של המורה לא נבדקו על מודלים אלה.
- המימוש נבדק בבדיקות יחידה מול שרת מדומה, **לא מול Zen בפועל** (בגלל המכסה).

### חיבור Supabase
1. צרו פרויקט ב-[supabase.com](https://supabase.com).
2. הריצו את המיגרציות לפי הסדר (SQL Editor, או `supabase db push`):
   - `supabase/migrations/0001_schema.sql` – טבלאות, קשרים, אילוצים ואינדקסים
   - `supabase/migrations/0002_rls.sql` – Row Level Security (כל משתמש רואה ומשנה רק את שלו)
   - `supabase/migrations/0003_storage_and_account.sql` – דלי קבצים פרטי `study-files`, ופונקציית מחיקת חשבון
3. ב-Authentication → Providers ודאו ש-Email מופעל (ובחרו אם לדרוש אישור אימייל). ב-URL Configuration הוסיפו את כתובת האתר ל-Redirect URLs.
4. העתיקו ל-`.env.local` את `Project URL` ו-`anon public key` (Settings → API).
5. הפעילו מחדש. במסך "הגדרות" → "חשבון וסנכרון" אפשר להירשם/להתחבר.

איך הסנכרון עובד: האפליקציה תמיד כותבת לאחסון המקומי (עובד גם offline) ומשקפת כל שינוי לענן. בהתחברות מתבצע מיזוג לפי מזהה (השרת מנצח בקונפליקט) ומה שקיים רק במכשיר עולה לענן. פירוט ב-[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## 🧪 בדיקות

```bash
npm run typecheck     # TypeScript
npm run lint          # ESLint (אפס אזהרות)
npm test              # בדיקות יחידה/API/סכימה (Vitest)
npm run build         # build פרודקשן
npm run test:e2e      # build + בדיקות קצה-לקצה (Playwright)
npm run test:all      # הכול ברצף
```

בפעם הראשונה (אם אין דפדפן Playwright): `npx playwright install chromium`.

מה נבדק בפועל (הרצה אחרונה: ראה [סטטוס](#-סטטוס-בדיקות)):
- **לוגיקה (Vitest):** חזרה מרווחת, בדיקת תשובות וציונים, אחוז שליטה והתאמת קושי, רצף ימים עם ימי מנוחה, XP ואי-צבירה כפולה, תוכנית הכנה למבחן, תכנון מפגשים, טיימר פומודורו, סימולציית מבחן, מיפוי נתונים ל-Supabase, שליפת חומר והפניות מאומתות.
- **API:** כל נתיבי ה-AI מול שרת Anthropic מדומה (סטרימינג, שגיאות 401/429/500, ניתוק רשת, קלט לא תקין, פלט מודל פגום, הגבלת קצב, הגנת CSRF/מקור, הזרקת הוראות בחומרים), ואימות אסימוני Supabase (משתמש/אורח/אסימון מזויף).
- **מסד נתונים:** המיגרציות רצות על Postgres אמיתי (PGlite) ונבדקים: כל הטבלאות, RLS בכולן, **בידוד בין משתמשים**, אילוצי תקינות, מחיקות שרשרת, מחיקת חשבון ומדיניות אחסון.
- **קצה-לקצה (Playwright, Chromium):** הקמה, יצירת מקצועות/נושאים/משימות, מבחן מלא (שאלות מכל הסוגים, טיימר, הגשה, ציון, הערכה עצמית), כרטיסיות, מצב ריכוז, לוח שנה ומערכת שעות, ספריית חומרים (כולל PDF אמיתי וסריקה), מורה AI, צילום שאלות, סיכומים, ייצוא/מחיקת נתונים, offline, PWA, נגישות אוטומטית (axe, מצב בהיר וכהה), ותצוגת מובייל.

## 🧩 מה עוד דורש הגדרה או פיתוח

דברים שחשוב לדעת – בלי עיגולי פינות:

1. **Anthropic האמיתי לא נבדק כאן.** לא היה מפתח בסביבת הפיתוח. כל הלוגיקה נבדקה מול שרת HTTP מדומה שמדמה את ה-Messages API (כולל SSE). כשתחברו מפתח אמיתי בדקו: שם המודל ב-`ANTHROPIC_MODEL`, איכות העברית, וקריאת תמונות. אם הפורמט שמוחזר שונה, ההתאמה נעשית בקובץ אחד: `src/services/ai/anthropic.ts`.
2. **Supabase אמיתי נבדק בבדיקה אחת (`npm run test:live`)**: סנכרון בין שני מכשירים, מחיקה, offline, קבצים ובידוד בין משתמשים. עדיין לא נבדקו הרשמה עם אישור אימייל ומחיקת חשבון. (הטקסט הבא נכתב לפני הבדיקה:) **Supabase אמיתי לא נבדק כאן.** הסכימה, ה-RLS והאחסון נבדקו על Postgres אמיתי (PGlite עם תחליפי `auth`/`storage`), ומנוע הסנכרון נבדק ברמת המיפוי והמיזוג (בדיקות יחידה), אבל **לא מול פרויקט Supabase חי**. מומלץ לבדוק ידנית: הרשמה, התחברות, יצירת נתונים, כניסה ממכשיר שני, העלאת קובץ, מחיקת חשבון.
3. **PDF סרוק (ללא טקסט):** מוצגת הודעה ברורה והקובץ נשמר, אבל אין OCR. לשם כך צריך שירות חזותי (למשל שליחת עמודים כתמונות ל-AI) – התשתית של ניתוח תמונות כבר קיימת (`/api/ai/vision`).
4. **תזכורות כשהאפליקציה סגורה:** דורשות Web Push (שרת + VAPID). כרגע התראות מערכת פועלות כשהאפליקציה פתוחה.
5. **תרגול במורה AI נספר בסטטיסטיקות** לפי בדיקת המורה (תגית מכונה בסוף תשובת הבדיקה, ללא XP). זו הערכה של מודל ולא מפתח תשובות, ולכן אפשרית טעות; לא נרשם במצב הסבר.
6. **הגבלת קצב בזיכרון** (`src/services/ai/ratelimit.ts`): מתאימה לשרת אחד. בפריסה serverless עם כמה מופעים כדאי להחליף לאחסון משותף (Upstash Redis / טבלת Supabase). הממשק זהה.
7. **מצב אורח:** כשמוגדר Supabase ומשתמש לא מחובר, ה-AI מוגבל לפי IP (`AI_GUEST_RATE_LIMIT_PER_DAY`). האכיפה בשרת. נתוני אורח נשארים במכשיר.
8. **ממשק באנגלית/LTR:** לא נבנה. האפליקציה בעברית ו-RTL בלבד (המבנה מאפשר הוספה: כל הטקסטים בקוד המסכים, אין מנוע i18n).
9. **Safari/iOS לא נבדק בדפדפן אמיתי** (יש כאן Chromium בלבד). נבדקו emulation של Pixel 7 ושל מסך 375×667. תמיכה ב-`capture` למצלמה, PWA ב-iOS וכו' מומלץ לבדוק על מכשיר.
10. **גופנים:** גופני מערכת (Heebo/Assistant אם מותקנים, אחרת ברירת מחדל של המכשיר) כדי לא להיות תלוים ברשת בזמן build. אפשר להוסיף `next/font/google`.
11. **shadcn/ui:** רכיבי ה-UI נכתבו בסגנון shadcn (cva + Tailwind + טוקנים), ללא Radix: חלונות מבוססי `<dialog>` מובנה. כך נשמרת נגישות (מלכודת פוקוס, ESC) עם פחות תלויות.
12. **Next 15 (יציב) ולא 16.**

2. הגדירו את משתני הסביבה מ-`.env.example` (`ANTHROPIC_API_KEY` כ-Secret, בלי `NEXT_PUBLIC_`).
3. Deploy. נתיבי ה-AI משתמשים ב-`maxDuration = 60`.

**שרת Node רגיל / Docker:** `npm run build && npm start` (פורט 3000, `PORT` לשינוי).

אחרי פריסה: ב-Supabase הוסיפו את הדומיין ל-Redirect URLs. בדקו `GET /api/health` ו-`GET /api/ai/status`.

## 🔒 אבטחה ופרטיות – בקצרה

- מפתח ה-API רק בשרת. נבדק אוטומטית שלא מופיע בדפדפן/HTML/חבילות.
- כל קלט נבדק עם Zod; הגבלת גודל/סוג קבצים (לקוח ושרת); הגבלת קצב לדקה וליום; הגנת מקור/CSRF.
- תוכן קבצים שהמשתמש העלה מטופל כ**נתונים בלבד** (תגיות ייעודיות + הוראה למודל + ניטרול הזרקת תגיות). המודל לא מבצע פעולות; האפליקציה לא נותנת לו כלים.
- הפניות למקורות מאומתות מול החומר שנשלח בפועל; הפניה לעמוד או חומר שלא קיימים מוסרת.
- RLS על כל הטבלאות, דלי קבצים פרטי לפי תיקיית משתמש, פרופיל קטין פרטי (אילוץ במסד).
- נשלח לספק ה-AI רק מה שצריך לתשובה (הודעות, קטעי חומר רלוונטיים, תמונות שצורפו).
- כותרות אבטחה: `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy` (מצלמה לאתר בלבד).
