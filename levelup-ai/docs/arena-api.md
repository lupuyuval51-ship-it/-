# ממשק זירת הלמידה

כל הנתיבים מתחילים ב־`/api`, דורשים session מאומת ונשארים תחת בדיקות הבעלות וה־Origin של השרת. קלט POST הוא JSON, למעט העלאות בתהליך התשלום הקיים. מפתחות הספק נשארים בשרת; אין להעביר אותם בבקשות הדפדפן.

## יצירה והיסטוריה

`POST /games/generate`:

```json
{
  "topic": "מתמטיקה: חיבור",
  "level": "beginner",
  "worldTheme": "future-city",
  "durationMinutes": 5,
  "locale": "he"
}
```

`topic` הוא טקסט של 2–240 תווים. הרמות הן `beginner`, ‏`intermediate` ו־`advanced`; משך המשחק 3, 5 או 7 דקות. העולם נבחר מרשימת העולמות של המנוע. `locale` אופציונלי (`he` או `en`); הגדרת המשחק כוללת תוכן בשתי השפות.

התגובה כוללת `game`, ‏`source` (`ai` או `demo`) והודעת מקור דו־לשונית ב־`sourceNotice`. מזהה המשחק הוא `game.dailyGameId`, המצב `knowledge-arena`, ובהגדרה שמונה שאלות. מפתחות התשובות מוסרים מהתגובה הציבורית.

פרמטרי `game.arena` מוגבלים ל:

| שדה | ערכים |
| --- | --- |
| `layout` | `courtyard`, `crossroads`, `islands` |
| `enemyCount` | 2–6 |
| `obstacleCount` | 4–12 |
| `ambience` | `day`, `dusk` |
| `waveCount` | 8 |

`GET /games/custom` מחזיר `games` עם מטא־נתונים של המשחקים הפרטיים של המשתמש ומכסת היצירה שנותרה (`remainingGenerations`). השדה `generatorIsDemo` מציין אם יצירה תשתמש בנתונים מקומיים בהיעדר מפתח AI; הוא נפרד מ־`isDemo`, המתאר את סביבת החשבון. `GET /games/custom/:id` מחזיר את ההגדרה המסוננת והזמינות. אין גישה למשחק פרטי באמצעות מזהה של חשבון אחר.

מכסת היצירה היומית: Free ‏1, Basic ‏3, Plus ‏6, Pro ‏12. בקשה מוגבלת או כשל בספק אינם מבטלים את מנגנון ההרשאות. יש לשמר את טופס המשתמש ולהציג את השגיאה שמחזיר השירות.

## התחלה ושמירת משחק

הנתיבים הקיימים `POST /games/start`, ‏`POST /games/event` ו־`POST /games/finish` מקבלים גם משחקים שנוצרו. להתחלה מוסרים `dailyGameId`; בתשובה מתקבל `attemptId`. אירועים כוללים מזהה ניסיון, אינדקס שאלה, בחירה וזמן, ולא ניקוד שהשרת חייב לקבל.

Free רשאי ליצור הגדרה ולראות תצוגה מקדימה, אך התחלת משחק מלא נדחית ב־403 עד זכאות פעילה. העלאת אישור bit אינה פותחת משחק: נדרש אישור מנהל לפי תהליך ההזמנות. השרת בודק בעלות, רצף אירועים, זמן, כפילויות ותגמולים. משחקים פרטיים אינם משתתפים בטבלת המובילים הציבורית.

בתוצאת סיום `totalQuestions` ו־`total` משמרים את מספר השאלות הכולל; `answered` מציין כמה נענו ו־`correct` כמה מהן נכונות. יש להבחין בין 2 תשובות מתוך 8 לבין השלמת המשחק. פקיעת זמן ללא תשובות אינה מעניקה XP, רצף, הישג או מקום בטבלת המובילים, ואינה צורכת את פרס ההשתתפות של ניסיון תקין מאוחר יותר.

## שאלות בהקשר למשחק

`POST /games/ask`:

```json
{
  "gameId": "the-selected-dailyGameId",
  "message": "איך לבדוק את הפתרון שלי?"
}
```

`gameId` אופציונלי. כאשר הוא מצורף, השרת בודק גישה והשיחה מוגבלת למשחק ולנושא שלו; כאשר אינו מצורף, ההקשר הוא הוראות משחק כלליות. הודעות משתמש הן תוכן לבדיקה, ואינן הוראות לשינוי הרשאות או ניקוד.

התגובה כוללת `message` עם `id`, ‏`role`, ‏`content`, ‏`isDemo`, ‏`source` ו־`createdAt`, את מכסת ההודעות שנותרה ב־`remaining`, וכן מצב חשבון מעודכן. `GET /games/messages?gameId=...` מחזיר היסטוריה בהקשר הנבחר, כולל מקור כל הודעה. בלי המזהה מוחזרת שיחת הוראות המשחק הכללית. המכסה משותפת למאמן הלימודי הקיים.

`source` נשמר כאחד מ־`user`, ‏`demo`, ‏`ai` או `hint`; יש להשתמש בו לתווית מקור ההודעה, ולא להסיק מהמצב הכללי של החשבון. בזמן שאלה פעילה בניסיון בעל ניקוד, תשובת המאמן נבחרת ממאגר רמזים והוראות ללא קריאה לספק חיצוני. לאחר המענה אפשר לקבל הסברים. כשל בספק המוגדר מחזיר 503 עם `AI_UNAVAILABLE`: שאלת המשתמש נשמרה, אך אין תשובת AI חדשה ואין החלפה שקטה ל־Demo.

הפעולה שומרת הודעות בלבד. תשובת AI אינה מפעילה משימות, משנה תשובות נכונות או מעניקה XP. הממשק צריך להציג מקור Demo ולהשהות קלט משחק בזמן פתיחת חלון השיחה, עם אפשרות סגירה וחזרה לבקר שהפעיל אותו.

## גבולות האימות

בזמן הריצה של SQLite נוספו `generated_game_owners`, שמקשרת משחק לבעליו ולמקור התוכן, ו־`game_coach_contexts`, שמקשרת הודעת מאמן למשחק או להקשר הוראות כללי ושומרת `source`. מיגרציית SQLite לגרסה 5 מוסיפה את מקור ההודעה למסד קיים וממלאת אותו לפי תפקיד, audit ודגל Demo. השיחה הרגילה של המסלול אינה מערבבת הודעות מהמשחק. ייצוא החשבון כולל את המשחקים ואת הודעות המשחק של אותו משתמש; מחיקה משביתה את המשחקים הפרטיים ומסירה את הנושא האישי מרשומת הבעלות. שלוש מיגרציות PostgreSQL הן עדיין בסיס עתידי שאינו מחובר לזמן הריצה; שתי טבלאות הזירה החדשות מחייבות מיגרציה מתאימה בעת חיבור מתאם PostgreSQL.

לכל משחק פרטי נשמרת מגבלת שני ניסיונות ביום המקומי. תגמול XP יומי ניתן פעם אחת במשותף לכל מצבי המשחק; יצירת משחקים נוספים אינה מכפילה את פרס ההשתתפות היומי.

בדיקת סכמה אינה סקירת מומחה או הוכחה לדיוק פדגוגי. היצירה והשיחה משתמשות בספק המרכזי ובסינון הקלט הקיים. הפעלת ספק רשת דורשת `AI_API_KEY`, ‏`AI_MODEL` וספק OpenAI, כפי שמתואר ב־README. ראו [דוח QA](QA.md) לתוצאות הרצה; חוזה API כשלעצמו אינו ראיה שהנתיב נבדק בדפדפן.
