# LEVELUP AI

פלטפורמת למידה בעברית ובאנגלית: מסלולים, משימות, מאמן לימודי, XP, משחקי 3D יומיים, Marketplace ותשלום bit באישור ידני. ממשק RTL בעברית כברירת מחדל, מצב כהה ובהיר, גופן Heebo מקומי וניווט המותאם לטלפון.

הגרסה כוללת יישום Next.js עם שרת ושמירה אמיתית ב־SQLite מקומי. אפשר להפעיל את כל מסע ההתנסות בלי מפתח AI ובלי ספק תשלום. **אין הרשמה:** לחיצה אחת בעמוד הבית פותחת חשבון בשרת, בלי אימייל, בלי סיסמה ובלי אימות. במצב Demo, משתמשים לדוגמה, התקדמות לדוגמה ותשובות המאמן מסומנים בהתאם. חשבון שנפתח נשמר במסד ולא רק בדפדפן, אבל עוגיית ההתחברות היא האסמכתה היחידה אליו.

**גבול הפריסה:** היישום מתאים להרצה בשרת Node יחיד עם דיסק מתמשך. סכמת PostgreSQL עם RLS מסופקת בנפרד; המתאם הפעיל עדיין SQLite. הגדרת `DATABASE_URL` לבדה אינה מעבירה את הנתונים ל־PostgreSQL. יש לקרוא את המגבלות לפני חשיפה לציבור.

## דרישות והתקנה

- Node.js 24 ומעלה, הכולל `node:sqlite`.
- pnpm 11; קובץ `pnpm-lock.yaml` נכלל כדי להתקין גרסאות עקביות.
- דפדפן מודרני. WebGL2 נדרש לגרפיקת 3D; חלופה דו־ממדית זמינה.
- דיסק שניתן לכתוב אליו עבור מסד הנתונים והעלאות פרטיות.

```sh
pnpm install --frozen-lockfile
```

העתיקו את `.env.example` אל `.env.local`. ב־PowerShell:

```powershell
Copy-Item .env.example .env.local
pnpm dev
```

פתחו [את האפליקציה המקומית](http://localhost:3000). אין צורך להריץ seed ידנית: טבלאות SQLite, תוכניות ברירת המחדל ושמונת המסלולים נוצרים בהפעלה הראשונה. במצב Demo נוצרים גם חשבונות ההתנסות.

```sh
pnpm typecheck
pnpm lint
pnpm test
pnpm build
pnpm start
```

פקודת `pnpm test` מקמפלת את בדיקות השירות/התוכן ואת התלויות שלהן באמצעות TypeScript ומריצה `node --test`. כך הבדיקות אינן תלויות ב־tsx או בגישת `os.userInfo` שעלולה להיחסם בסביבות Windows מוגבלות. פלט הקימפול נשמר בתיקייה חדשה תחת `work/test-runs`; אפשר לבחור מיקום באמצעות `LEVELUP_TEST_WORK_DIR`. הבדיקות משתמשות ב־SQLite בזיכרון, מאמן Demo ואימייל Demo ואינן שולחות בקשות לספקי תשלום/AI.

לבדיקות דפדפן, התקינו Chromium של Playwright והריצו:

```sh
pnpm exec playwright install chromium
pnpm test:e2e
```

`playwright.config.ts` משתמש בשרת מקומי קיים בפורט 3000, או מפעיל שרת פיתוח אם אינו זמין. הגדירו `PLAYWRIGHT_NO_SERVER=true` כדי לבדוק רק שרת שכבר פועל, בלי להפעיל שרת נוסף. ב־Windows עם Chrome מותקן הוא משתמש ב־channel chrome; אחרת יש להתקין Chromium כמתואר לעיל. אפשר לבחור `PLAYWRIGHT_CHANNEL` ו־`PLAYWRIGHT_BASE_URL` (localhost בלבד). הבדיקות יוצרות חשבונות Demo ייחודיים ושומרות trace וצילום בכשל תחת `work/e2e-artifacts` או `LEVELUP_E2E_OUTPUT_DIR`. הן בודקות פתיחת חשבון מעמוד הבית ללא טופס, onboarding והשלמה עם XP מתמשך, שפה/תמה ושמונה רוחבים, שלוש הזמנות bit, אישור מנהל ורענון הרשאות וחסימת משחק למשתמש Free. בדיקות הזירה הנוספות נמצאות ב־`tests/mobile-arena.e2e.spec.ts`; תוצאות ריצה מאומתות מפורטות בדוח QA.

## נתונים, גיבויים ומיגרציות

SQLite נשמר כברירת מחדל ב־`data/levelup.sqlite`, עם קובצי WAL/SHM בעת פעילות. העלאות נשמרות ב־`data/uploads`; אין לשים את התיקייה תחת `public`. אפשר לשנות מיקום באמצעות `LEVELUP_DB_PATH` ו־`LEVELUP_UPLOAD_DIR`.

- יש לגבות את SQLite וההעלאות יחד באמצעות גיבוי SQLite עקבי או כשהיישום עצור. העתקת קובץ DB לבדו בזמן כתיבה אינה גיבוי מלא בהכרח.
- אתחול אינו מאפס נתונים קיימים. עריכת תוכן בקובץ seed אינה מחליפה אוטומטית מסלולים שכבר נשמרו.
- להרצת התנסות נקייה, הגדירו נתיב מסד חדש ותיקיית העלאות חדשה. אין למחוק נתוני משתמשים לצורך בדיקה.
- אין להפעיל כמה מופעי שרת עם דיסקים מקומיים נפרדים ולצפות לסנכרון.
- שורות שפג תוקפן ב־`sessions`, `auth_tokens`, `rate_limits` ו־`demo_mail` נמחקות אוטומטית לכל היותר פעם בשעה, כדי שקובץ המסד לא יגדל ללא הגבלה. המחיקה נוגעת רק לרשומות שכבר אינן בתוקף.

ליצירת בסיס PostgreSQL עתידי, הריצו במסד ריק עם חשבון מנהל שמורשה ליצור roles עם BYPASSRLS:

```sh
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f migrations/001_postgresql.sql
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f migrations/002_integrity_and_payment.sql
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f migrations/003_private_paths_and_reinforcement.sql
```

המיגרציות כוללות קשרים, אינדקסים, סטטוסים, תאריכים, סכומים באגורות, תוכניות, קטגוריות, חמש תבניות משחק ויומן פעולות שאינו ניתן לעריכה. המיגרציה השנייה מוסיפה מפתחות מורכבים למניעת שיוך העלאה/הזמנה למשתמש אחר ופונקציית אישור תשלום אטומית המותרת רק לשירות שרת מאומת. היא מיועדת להפעלה פעם אחת על מסד ריק. הן אינן מייבאות משתמשי Demo או מעתיקות את SQLite. המיגרציה השלישית מוסיפה בעלות על מסלולים פרטיים ותרגולי חיזוק, עם RLS לפי בעלים; מסלול פרטי אינו נחשף כאשר סטטוסו משתנה למאושר, ואינו יכול להיכנס ישירות ל־Marketplace.

`levelup_reader` מקבל קריאת שורות של משתמש מורשה בלבד; סיסמאות, טוקנים, מפתחות תשובה, נתיבי קבצים והערות תשלום פנימיות אינם חלק מהרשאת הקריאה. השרת צריך לאמת session ואז להגדיר `SET LOCAL app.user_id` בתוך טרנזקציה. אין לתת ללקוח לבחור את המזהה או להתחבר למסד ישירות. `levelup_service` מיועד אך ורק לתהליך שרת מהימן לאחר בדיקות הרשאה וסכמה; הוא עוקף RLS לצורך פעולות עסקיות וניהול. אין לתת role זה למשתמש קצה.

כדי לעבור ל־PostgreSQL יש לממש מתאם SQL ל־`db.ts`, להמיר placeholders ופונקציות SQLite, למפות את העמודות, להריץ מיגרציית נתונים, ולהריץ מחדש בדיקות בידוד בין משתמשים, תשלומים, כפילויות ו־RLS. RLS אינו זמין במנוע SQLite; ההפרדה הפעילה כרגע נאכפת בשאילתות ובשכבת ההרשאות בשרת.

## חשבונות ובטיחות קטינים

אין מסך הרשמה, אין אימות אימייל ואין איפוס סיסמה. `POST /api/auth/guest` פותח חשבון מלא בשרת ומחזיר עוגייה ל־365 יום; לחיצה חוזרת עם עוגייה קיימת מחזירה את אותו חשבון ולא יוצרת חשבון נוסף. מכיוון שאין טופס, יצירת חשבונות מוגבלת בקצב: `GUEST_BURST_LIMIT` (60 לדקה כברירת מחדל) לכלל השרת, ו־`GUEST_NETWORK_LIMIT` לכל כתובת כאשר `TRUST_PROXY=true`. החלון הגלובלי קצר בכוונה — מכסה שעתית מוחלטת הייתה מאפשרת ללקוח אנונימי אחד לשרוף אותה ולנעול כל מבקר אמיתי מחוץ לאפליקציה עד סוף השעה. להגנה אמיתית מפני יצירה המונית נדרש reverse proxy עם `TRUST_PROXY=true`; המגבלה הגלובלית היא בלם ולא חומה.

**המשמעות למשתמש:** אין דרך לשחזר חשבון. ניקוי נתוני הדפדפן, מכשיר אחר או גלישה פרטית פירושם חשבון חדש. הדבר נאמר במפורש בעמוד הבית.

בהיעדר הרשמה אין שנת לידה מוצהרת, ולכן **חשבון חדש מטופל כקטין עד שיוצהר אחרת**: הפרופיל פרטי וכפוי, רכישה דורשת אישור מפורש של הורה או בעל אמצעי תשלום, ופרסום מסלול בתשלום חסום. שנת לידה נמסרת בהגדרות בלבד ורק היא פותחת פעולות למבוגרים. זהו כלל מוצר ולא מנגנון לאימות גיל או זהות, ואינו קביעה שהוא מספק בכל מדינה. אין צ׳אט חופשי או איסוף מיקום מדויק.

חשבון צוות אינו נוצר דרך היישום כלל. הפקודה הבאה יוצרת חשבון מנהל חדש ומדפיסה סיסמה חד־פעמית, או מקדמת חשבון קיים; `--reset-password` מנפיק סיסמה חדשה ומנתק את כל ההפעלות. הפעולה נרשמת ביומן.

```sh
node --env-file=.env.local scripts/promote-admin.mjs admin@example.com
```

כניסת הצוות מריצה scrypt חוסם בכל ניסיון, גם עבור חשבון שאינו קיים (כדי לא לחשוף אילו כתובות רשומות). מכיוון שהמזהה שנשלח נשלט בידי הפונה, מגבלה לפי כתובת אימייל לבדה אינה מגבלה כלל — לכן קיימת גם תקרה לכל הנתיב, `AUTH_LOGIN_LIMIT` (30 לרבע שעה), שאיש אינו יכול לעקוף. מסך `/login` משמש את הצוות בלבד. חשבונות לומדים נושאים סיסמה אקראית שאיש אינו מחזיק, ולכן לא ניתן להיכנס אליהם בסיסמה בשום מצב. אין להפוך שדה role מהלקוח להרשאת מנהל.

## שירות AI — Claude API

ללא מפתח, המאמן משתמש ב־DemoProvider עם רמזים, מטרות והקשר מן המסלול. תשובות אלה מסומנות Demo. הן אינן הוכחה לניתוח סמנטי חופשי של כל הגשה.

להפעלת Claude הגדירו:

```dotenv
AI_PROVIDER=anthropic
ANTHROPIC_API_KEY=your-server-side-key
# אופציונלי: מודל אחר מ־claude-opus-5, ועומק חשיבה low|medium|high|xhigh|max
AI_MODEL=
AI_EFFORT=
```

ברירת המחדל היא `claude-opus-5` עם חשיבה אדפטיבית (`thinking: adaptive`). מפתח שמוגדר יחד עם `AI_PROVIDER` אחר נכשל בגלוי בשגיאת 503 ואינו נופל בשקט חזרה ל־Demo. המפתח נשאר בשרת ואינו נשלח בגוף הבקשה.

המתאם משתמש ב־Messages API עם `output_config.format` מסוג `json_schema` הנגזר מסכמת Zod, ולכן התשובה מאומתת פעמיים: פעם מול הסכמה בצד הספק ופעם ב־Zod אצלנו. יש timeout לכל ניסיון ולכל היותר שני ניסיונות; `maxRetries` של ה־SDK מכובה כדי שבקשה בודדת לעולם לא תחויב פעמיים. מכיוון שהחשיבה חולקת את תקציב התשובה, `max_tokens` בפועל גדול פי שלושה מהתוכן המבוקש. שימוש נרשם ביומן בלי המפתח. בקשת המאמן כוללת רק הקשר לימודי נדרש. יש לבדוק בנפרד את תנאי הספק לפני טיפול בנתוני קטינים.

המאמן אינו מפעיל קוד, מעניק הרשאות, מאשר תשלום או משנה תגמול. הצעותיו הן נתונים שעוברים סכמה. התאמות מסלול נוצרות בכללי השרת ומוצגות למשתמש לפני שינוי משמעותי. יצירת מסלול למיומנות חופשית משתמשת בשירות המשותף כאשר מוגדר מפתח. ללא ספק, נבחר מסלול מוכר או נבנית מסגרת לימוד כללית המסומנת Demo כמפורט להלן. אין הערכה אוטומטית של תוכן קובץ או ביקור בקישור שנשלח.

### מכסת AI לפי הסכום ששולם

המכסה היומית אינה קבועה לכל מדרגה אלא נגזרת מהסכום שנגבה בפועל בהזמנה המאושרת של המנוי הפעיל:

```
הודעות מאמן ליום = AI_FREE_DAILY_MESSAGES + (סכום ששולם × AI_MESSAGES_PER_NIS)
יצירות משחק ליום = AI_FREE_DAILY_GAMES   + (סכום ששולם × AI_GAMES_PER_NIS)
```

בברירות המחדל (8 + ₪×2.5, ו־1 + ₪×0.3) מתקבל: Free 8 הודעות ומשחק אחד, Basic ב־₪9 מקבל 31 ו־4, Plus ב־₪19 מקבל 56 ו־7, Pro ב־₪39 מקבל 106 ו־13. שינוי מחיר בהגדרות המנהל משנה אוטומטית את המכסה של מנויים חדשים, ומי שכבר שילם שומר על המכסה שרכש, מפני שהחישוב נשען על הסכום שנלכד בהזמנה ולא על מחיר המחירון הנוכחי. שאר ההרשאות — גישה למשחקי 3D, מספר מסלולים פעילים והיסטוריה — נשארות לפי המדרגה. שיחות המאמן במסלול ובזירה חולקות את אותה מכסה.

## יצירת מסלול אישי פרטי

כאשר המשתמש מזין מיומנות חופשית ואינו בוחר מסלול קטלוג מפורש, השרת משתמש ב־`path-generation.ts`:

- עם `ANTHROPIC_API_KEY` ו־`AI_PROVIDER=anthropic` (גם ערך ספק ריק מתקבל), מתקבלת טיוטה מובנית דרך Messages API. השרת דורש 3–5 פרקים, 2–4 משימות בכל פרק, כותרות ייחודיות, שלוש אפשרויות שונות לכל שאלה ופרויקט סיום. הפלט עובר Zod ובדיקות תוכן לפני טרנזקציית שמירה.
- ללא מפתח, נושא מוכר בוחר אחד משמונת מסלולי המערכת עם תווית `demo-curated`. נושא אחר יוצר `demo-study`: שישה צעדים לבחירת מקור אמין, תכנון, תרגול ופרויקט בהתאם למטרה. המסך מסביר שזו מסגרת עבודה כללית, ולא קורס מקצועי שנוצר ב־AI. לא מתבצעת החלפה סמויה למסלול HTML.
- מסלול חדש, פרקים, משימות, רשומת בעלות והצטרפות נשמרים יחד. המסלול פרטי ורק בעליו רואה אותו בקטלוג החשבון שלו. הוא אינו מתפרסם ב־Marketplace; גם שימוש במזהה שלו בחשבון אחר נדחה.
- מקור המסלול והאם מדובר ב־Demo נשמרים ומוצגים. במסלול AI מצוין שאין סקירת מומחה. אין פרסום אוטומטי, שינוי זכויות מנוי או ביצוע קוד מתוך תשובת המודל.

הבקשה למודל כוללת רק מיומנות, מטרה, רמה, זמן יומי, תאריך יעד והעדפות לימוד. מסננים בסיסיים מסירים דפוסי סיסמאות, מפתחות, אימיילים וטלפונים מטקסט חופשי; אין לשלוח מידע אישי מיותר. נתוני חשבון, שנת לידה, תשלומים והיסטוריית צ׳אט אינם מצורפים לבקשת יצירת מסלול.

כל הקריאות מוזרמות (streaming). זה מכוון: ה־SDK מחשב timeout לבקשה שאינה מוזרמת כ־`60 דקות × max_tokens / 128000`, כך שתקציב גדול חורג מכל timeout סביר. הזרמה מסירה את התקרה הזאת ושומרת על החיבור פתוח. בקשת יצירת מסלול מוגבלת ל־240 שניות לכל ניסיון ולשני ניסיונות בסך הכול; בקשות המאמן מוגבלות ל־60 שניות לניסיון. מענה שאינו עובר בדיקה אינו נשמר. ההפקה מוגבלת ל־12,000 טוקנים, והמערכת קובעת מזהים ומגבילה XP ל־80 במשימה רגילה ול־120 בפרויקט. לא מתקבלים קישורי משאבים שלא נבדקו מהמודל. מכסת יצירת המסלולים ב־24 שעות נשארת 3 ל־Free/Basic, 10 ל־Plus ו־20 ל־Pro, בנוסף למגבלת המסלולים הפעילים; מכסת המשחקים והמאמן נגזרת מהסכום ששולם כמתואר למעלה. גבול היממה למכסות ולפרס היומי הוא UTC ולא אזור הזמן שבפרופיל — אזור הזמן ניתן לעריכה בידי הלומד, ולכן אינו יכול להגדיר גבול שמזכה בפרס.

מטרות מסוכנות נדחות. בתחומי בריאות ופיננסים נוצרים מושגים ותרגולים כלליים בלבד, ללא טיפול, מינון, עומס אימון או המלצות לעסקה אישית. מסננים מבוססי כללים אינם תחליף לביקורת מומחה. בדיקות הסכמה והפרטיות המקומיות משתמשות בספק מוזרק ומבוקר; בדיקת Messages עם מפתח אמיתי עדיין דורשת הגדרת שירות חיצוני.

## מנויים ותשלום ידני ב־bit

| תוכנית | מחיר חודשי ברירת מחדל | מסלולים פעילים | משחק מלא |
| --- | ---: | ---: | --- |
| Free | ₪0 | 1 | תצוגה מקדימה |
| Basic | ₪9 | 1 | כן, עד שני ניסיונות |
| Plus | ₪19 | 5 | כן |
| Pro | ₪39 | 50 כגבול שימוש סביר | כן |

ההרשאות מרוכזות ב־`src/lib/server/config.ts`. מחיר אינו הוכחת זכאות. בדיקת מנוי פעיל ותאריך תפוגה מתבצעת בשרת. משחקי Free נחסמים בשרת גם אם הלקוח שונה. שיפור אישי נשמר בנפרד מתוצאת הניסיון הראשון לצורך השוואה הוגנת.

מספר המקבל נקרא מהגדרה מרכזית אחת: `BIT_PAYMENT_PHONE=0526262828`. שינוי המספר נעשה בסביבה, לא ברכיבים. המחיר נשמר בזמן יצירת ההזמנה כך ששינוי מחיר עתידי אינו משנה הזמנה קיימת.

1. המשתמש בוחר תוכנית או מסלול בתשלום; השרת יוצר מספר הזמנה וסכום.
2. המסך מציג את המספר, הסכום והוראה לציין את מספר ההזמנה בהערת ההעברה.
3. המשתמש פותח את bit בעצמו ומשלם. אם הוגדר קישור אמיתי, HTTPS ומאומת בידי בעל השירות, ניתן להגדיר `BIT_PAYMENT_URL` וגם `BIT_PAYMENT_URL_VERIFIED=true`. ברירת המחדל היא ללא קישור. אין deep link מומצא.
4. המשתמש מעלה PNG, JPEG, WebP או PDF עד 5 MB. נבדקים גודל, סוג נטען וחתימת קובץ; קבצים נשמרים בפרטיות.
5. ההזמנה עוברת לבדיקה. העלאה **אינה** מפעילה מנוי. התהליך מסביר: ״התשלום באמצעות bit נבדק ידנית. הגישה תופעל לאחר אישור ההעברה.״
6. מנהל בודק את ההעברה באפליקציית bit שלו ומשווה סכום והזמנה. צילום מסך לבדו אינו הוכחת קבלת כסף.
7. מנהל מאשר או דוחה במסך הניהול. אישור מתבצע בטרנזקציה, נשמר מי אישר ומתי, ומוגן מפני אישור כפול.
8. אישור מפעיל מנוי מוגבל בזמן או רכישת מסלול, מוסיף הודעה ומאפשר רענון הרשאות בלי כניסה מחדש.

מנוי חודשי אינו חיוב חוזר אוטומטי. בתום התוקף יש ליצור הזמנה נוספת. החזר `refunded_manually` הוא תיעוד החלטת מנהל; החזרת הכסף עצמה נעשית מחוץ למערכת. נתוני מכירה ועמלה נשמרים, אך כסף אינו מועבר ליוצרים אוטומטית.

`PaymentAdapter` הוא נקודת החיבור לספק רשמי עתידי. מתאם חדש יצטרך מזהי עסקאות, אימות חתימות webhook, סכום ומטבע מהשרת, idempotency, reconciliation והחזר כספי. אין לפתוח גישה בעקבות callback מהדפדפן בלבד.

## מנוע Daily 3D Quest

### זירת ידע לפי נושא

מסך המשחק מרכז שלוש פעולות: לשחק, ליצור משחק ולשאול AI. בוחרים נושא, רמה ומשך של 3, 5 או 7 דקות. השירות מחזיר משחק פרטי מסוג `knowledge-arena`: שמונה שאלות, זירה בתבנית מוגדרת, מכשולי מחסה ורובוטים. המשחק מציג את מקור התוכן, ומאפשר לשאול שאלה בהקשר למשחק שנבחר.

כאשר מוגדר Claude, הוא מייצר נתונים לפי JSON Schema בלבד: כותרת, שמונה שאלות דו־לשוניות ופרמטרים לזירה. מותרות שלוש תבניות זירה, 2–6 רובוטים ו־4–12 מכשולים; המודל אינו יוצר קוד, נכסים, הרשאות או פרסים. כל בקשת יצירה מוגבלת ל־90 שניות ולשני ניסיונות בסך הכול, עד 6,000 טוקנים לתוכן. תשובות שאינן עוברות את הסכמה ובדיקות התוכן אינן נשמרות כמשחק.

ללא מפתח פועל Demo מסומן: תרגילי חשבון מחושבים מקומית; נושאים מוכרים משתמשים בשאלות מהמסלולים המוכנים, עם חזרות מסומנות; נושא אחר מקבל תרגול של שיטות למידה כלליות. Demo אינו מוצג כמאגר מומחה לכל תחום. גם תוכן שנוצר במודל אינו מסומן כמאושר בידי מומחה.

מכסת יצירת משחקים ביום היא 1 ל־Free, ‏3 ל־Basic, ‏6 ל־Plus ו־12 ל־Pro. יצירת הגדרה אינה פותחת זכאות למשחק מלא: Free מקבל תצוגה מקדימה, והשרת דורש Basic ומעלה להתחלה. משחקים שנוצרו פרטיים לבעליהם ומופרדים מטבלת המובילים הציבורית. ניקוד ותוצאות ממשיכים לעבור דרך שירות המשחק הקיים ותקרת התגמול היומית.

שיחת AI במשחק מיועדת להוראות, לנושא ולהסברים, ומשתמשת במכסת המאמן הקיימת. ההיסטוריה מופרדת לפי משחק; ללא משחק נבחר זו שיחת הוראות כללית למשחקים. בשאלה פעילה שנושאת ניקוד, השרת נותן רמז מתוך מאגר מוגבל (`source: hint`) ואינו פונה למודל שיכול לחשוף את הפתרון. מקור כל הודעה נשמר: משתמש, רמז, Demo או AI. מחוץ לשאלה פעילה, כשל בספק מוגדר מחזיר שגיאה ושומר את שאלת המשתמש; אין החלפה שקטה לתשובת Demo. תשובת שיחה אינה משנה ניקוד, תשובה, מנוי או הרשאה. חוזי הקלט והפלט מפורטים ב־[ממשק שירות הזירה](docs/arena-api.md).

### המנוע והתמות

המנוע נטען רק בכניסה למשחק. דף הבית וה־Dashboard משתמשים באיור קל ואינם טוענים Three.js. הסצנות נבנות מקוד מקומי ותבניות; AI אינו מייצר קוד משחק להרצה.

לצד זירת הידע נשמרו חמשת המצבים Answer Gates, Knowledge Escape Room, Collect and Sort, Build the Path ו־Boss Quiz. חמש התמות הן עיר עתידנית, אי צף, מעבדת AI, טירה ועולם קוביות. המשחק היומי משתמש במשימות המסלול; משחק פרטי משתמש במקור התוכן שמצוין במסך. מאגר הפתיחה קטן ולכן שאלות יכולות לחזור.

ממשק המשחק מציג התקדמות לפי תשובות שנשמרו, ומאפשר לצמצם את השאלה כדי לפנות מקום לעולם בלי לאבד את הבחירה. ההסבר לתשובה האחרונה נשאר לקריאה עד לחיצה על ״לתוצאות המשחק״. אפשר לעבור לדו־ממד דרך תפריט העצירה; אם טרם נבחרה תשובה, נדרשת בחירה לפני שליחה. הזמן ממשיך להיספר בשרת גם בזמן עצירת העולם או שיחה עם המאמן.

בזירה, קו הכיוון מציג מחסה שחוסם ירי; רובוטים מציגים אזהרה ונועלים כיוון לפני התקפה, כך שאפשר להתחמק בפועל. פגיעה במגן מוצגת כהודעה קצרה. המצבים הנוספים כוללים סימון ברור של היעד, נתיב חזרה למסירת פריט, מגירה ומנגנון נעילה בחדר הבריחה, מקטעי גשר עם משוב, ואזהרת נתיב לפני מתקפת Boss. משוב נכון/שגוי מתקבל מתשובת השרת; פגיעה במכשול אינה מוצגת כאילו הייתה טעות בשאלה.

מוזיקה ואפקטים ניתנים לשליטה בנפרד גם בתפריט העצירה. לכל עולם מנגינה מסונתזת מקורית; המנוע מגביל את מספר הקולות במקביל, משחרר משאבים ביציאה ומטפל גם בדחיית הרשאת שמע. עצירה, אובדן מיקוד או אובדן לכידת מצביע משחררים את קלט התנועה והירי כדי שלא יישארו לחוצים.

השרת שומר הגדרת אתגר, seed, גרסה, קבוצה, שאלות וניסיון. כל תשובה עוברת בדיקת סדר וזמן בשרת; הניקוד מחושב בשרת, ותוצאה כפולה אינה מעניקה פרס נוסף. בדיקות זמן ואירועים מצמצמות רמאות בסיסית, אך אינן מערכת anti-cheat מתקדמת. אתגרים מתחלפים לפי יום באזור הזמן בהעדפות.

- מחשב: חצים/WASD לתנועה, 1–4 לבחירת תשובה ו־Escape לעצירה. בזירה E יורה ורווח מפעיל זינוק; במצבים המקוריים E מפעיל פעולה, רווח קופץ וגרירת עכבר מסובבת מצלמה.
- טלפון: בזירה משתמשים בג׳ויסטיק, כפתור ירי שאפשר לגרור לכיוון ידני וכפתור זינוק. במצבים המקוריים יש כפתורי קפיצה ופעולה. ניתן לשנות את צד הבקרים בהגדרות.
- קיים מצב איכות נמוכה, כיבוי צללים, אפשרויות מוזיקה ואפקטים והפחתת תנועה.
- החלפת טאב עוצרת משחק; אובדן WebGL מציע מצב דו־ממדי. מצב 2D מפעיל את אותם כללי תשובה ושמירה.
- טעינת `public/models/explorer.glb` המקורי (כ־4 KB, CC0, ללא טקסטורות) כוללת fallback גאומטרי. הרישיון ב־`public/models/LICENSE.txt`. חומרים וגאומטריות משוחררים ביציאה. הצלילים מסונתזים מקומית מתבניות מקוריות.
- 60 FPS הוא יעד תכנון; יש למדוד בחומרה אמיתית לפני התחייבות לביצועים.

להוספת עולם: הרחיבו `WORLD_THEMES`, `WORLD_LABELS` ו־`WORLD_PALETTES` ב־`src/lib/game.ts`; הוסיפו יצירת סביבה ב־`scene.ts`, בחירה מותרת בשרת ומחרוזות. ודאו שגם 2D, mobile ואיכות נמוכה עובדים. שמרו רישיונות וקבצים קטנים לכל נכס חיצוני.

להוספת מצב: הגדירו מזהה וחוזה נתונים, הוסיפו כללי תנועה ואינטראקציה במנוע וגרסת חלופה ב־GamePlayer, הרחיבו את סכמת השרת וחישוב התוצאות, והוסיפו בדיקות לפני שהמנהל יכול לפרסם אותו. שינוי משמעותי מחייב גרסת תבנית חדשה כדי לא לפרש מחדש תוצאות עבר.

## PWA, קבצים ובטיחות

המניפסט וסמל SVG נכללים. `public/sw.js` שומר רק רשימה סגורה של נכסים ציבוריים סטטיים. API, sessions, דפי חשבון וקבצים פרטיים אינם נשמרים ב־Service Worker. זהו בסיס PWA; אין הבטחה לשימוש מלא בחשבון כשהשרת לא זמין. יש חיווי Offline ושמירת טיוטות בדפדפן בהתאם למסך.

סיסמאות נשמרות כ־scrypt עם salt, sessions בטוקנים אקראיים ששומרים רק hash, cookies מוגדרים HttpOnly/SameSite ו־Secure ב־HTTPS. בקשות כתיבה נבדקות מול Origin; יש בדיקות Zod, שאילתות עם פרמטרים והגבלות בקשות. כל פעולה רגישה בודקת בעלות או תפקיד בשרת. הוכחות תשלום מוגשות דרך נתיב מאומת ואינן זמינות כקובץ ציבורי. קובץ שנכתב לאחסון ונדחה בבדיקת ההרשאות נמחק מיד ואינו נשאר כקובץ יתום.

כל תגובה נושאת כותרות אבטחה: `Content-Security-Policy` שמגביל מקורות לאותו origin בלבד (`frame-ancestors 'none'`, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`), `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, `Cross-Origin-Opener-Policy` ו־`Cross-Origin-Resource-Policy`. ה־CSP עדיין כולל `'unsafe-inline'` לסקריפטים מפני ש־Next מזריק סקריפט אתחול מוטבע; `'unsafe-eval'` מתווסף בסביבת פיתוח בלבד. לפני פריסה ציבורית מומלץ לעבור ל־nonce ולהסיר `'unsafe-inline'`.

`TRUST_PROXY=false` היא ברירת המחדל. הגדירו `true` רק מאחורי reverse proxy מהימן שמחליף את `X-Forwarded-For` ומונע גישה ישירה לשרת היישום. רק אז כתובת IP תקינה בכותרת משמשת להגבלת קצב לפי רשת. מגבלות לפי חשבון או מזהה פעולה נשארות פעילות גם כשהכותרת אינה מהימנה; אין לאפשר ללקוח לספק זהות רשת עצמאית.

בדיקת חתימת קובץ אינה סריקת נוזקה, פירוק תוכן או הסרת metadata. לפני שימוש ציבורי יש להוסיף סריקה/הסגר, הסרת EXIF לתמונות בהתאם לצורך, מדיניות שמירה ומחיקה מתוזמנת וגיבוי מאובטח. אין להריץ קבצים שהועלו או קוד של משתמשים בשרת היישום.

## פריסה

פריסה מקומית ב־Docker:

```sh
docker build -t levelup-ai .
docker run --name levelup-ai -p 3000:3000 --env-file .env.local -v levelup-data:/app/data levelup-ai
```

הדוגמה קוראת את מצב הסביבה שנבחר בקובץ. לפריסת התנסות השתמשו ב־Demo; לפריסה אמיתית הכינו קובץ נפרד עם `DEMO_MODE=false`, HTTPS וסודות שרת בלבד. Docker פועל כמשתמש שאינו root ומשתמש ב־volume קבוע. ה־Dockerfile דורש גישה לרשת בזמן התקנת תלויות ובנייה, ולא נבדק מול ספק אירוח ציבורי במסגרת העבודה המקומית.

ב־`NODE_ENV=production`, היעדר `DEMO_MODE` משמעו מצב אמיתי; Demo דורש את הערך המפורש `true`. במצב ייצור אמיתי `APP_URL` חייב להיות origin תקין ב־HTTPS, ללא שם משתמש, סיסמה, נתיב או query. תצורה חסרה או לא תקינה חוסמת בקשות API; ניתן לבנות את החבילה לפני הזרקת משתני הסביבה. בדיקת חבילת production מקומית אפשרית רק עם `DEMO_MODE=true` מפורש וכתובת localhost.

לפני פריסה לציבור:

1. השתמשו במסד חדש; כיבוי `DEMO_MODE` חוסם כניסה לחשבונות Demo שנוצרו קודם, אך אינו מוחק את נתוני ההתנסות. השתמשו במסד ייצור חדש והפרידו בין הנתונים.
2. הגדירו כתובת HTTPS ו־reverse proxy שאינו מקבל Origin/Host מזויפים, מגבלת גוף בקשה ומדיניות גיבוי.
3. צרו חשבון מנהל עם `scripts/promote-admin.mjs`, שמרו את הסיסמה החד־פעמית במנהל סודות, והחליפו אותה מיד אחרי הכניסה הראשונה.
4. אמתו בפועל את חשבון bit ואת מספר המקבל; הוסיפו קישור רק לאחר בדיקתו. השלימו תנאי שימוש, פרטיות, הסכמה ומדיניות החזרים עבור הישות המפעילה.
5. הגדירו ניטור שגיאות וזמינות, סריקת העלאות, מחיקת מידע מתוזמנת והתראות על פעולות מנהל.
6. הריצו Build, TypeScript, lint, בדיקות שירות ו־E2E, בידוד משתמשים ומסכי 320–1440px מול תצורת הייצור.
7. לשרתים מרובים, אחסון serverless או תשתית עם filesystem זמני יש לחבר PostgreSQL ואחסון פרטי חיצוני קודם.

## מגבלות נוכחיות

- SQLite הוא מסד זמן הריצה; PostgreSQL/RLS מסופק כמיגרציית תשתית ואינו פעיל באפליקציה.
- ניתן ליצור מסלול פרטי בעזרת Claude כאשר מוגדר מפתח; הפלט עובר סכמה ובדיקות מבניות, אך אינו מאומת בידי מומחה בתחום ואין הבטחה לדיוק או התאמה לכל מיומנות. ללא ספק משתמשים במסלול מוכן או במסגרת Demo כללית מסומנת. אין אבחון מקצועי של רמת ידע.
- משימה מעשית נבדקת לפי קלט וכללי השלמה מוגדרים; לא מתבצע ניתוח אוטומטי מלא של הקובץ, הפרויקט או כתובת הקישור. ציון אינו הסמכה מקצועית.
- המאמן המקומי מדומה; מאמן רשת דורש הגדרת ספק ומודל. חסימות טקסט בסיסיות אינן תחליף למערכת מתינות אנושית מלאה.
- אין חשבון שניתן לשחזר: ניקוי נתוני הדפדפן מנתק את המשתמש מכל ההתקדמות שלו לצמיתות. מי שירצה חשבון עמיד יצטרך להוסיף שכבת זיהוי משלו. אימות גיל מסתמך על הצהרה בלבד, ובהיעדר הצהרה החשבון מטופל כקטין.
- תשלום, החזר ותשלום ליוצר נעשים ידנית. אין חיבור אוטומטי ל־bit ואין גבייה חוזרת.
- משחקי הפתיחה קצרים ומשתמשים במאגר שאלות קטן. כמות התוכן, איכות הביצועים במכשירים חלשים ויכולת מניעת רמאות מחייבות הרחבה ובדיקת שטח.
- אין צ׳אט פתוח, תשתית וידאו, אפליקציה native, סליקה אוטומטית או תשתית למיליוני משתמשים.
- תנאי שימוש ופרטיות במוצר הם נוסח פתיחה תפעולי שיש להתאים לפריסה ולמדינה; אין טענה לאישור משפטי או לביקורת אבטחה חיצונית.
