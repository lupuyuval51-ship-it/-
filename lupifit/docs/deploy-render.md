# העלאת LUPU-FIT ל-Render (חינם) עם מסד נתונים ב-Neon

מדריך קצר לאדם לא טכני. התוצאה: כתובת `https://….onrender.com` שעובדת בטלפון, בלי שרת לנהל.
הקבצים שהמדריך משתמש בהם כבר קיימים ב-repo: `render.yaml` (בשורש) ו-`lupifit/Dockerfile`.

> **לא נחוץ לאפליקציה לאנדרואיד.** האפליקציה שמתפרסמת ב-Google Play עובדת היום כולה בתוך הטלפון (מצב מכשיר), בלי שרת
> ובלי מסד נתונים לשלם עליהם: [device-mode-he.md](device-mode-he.md). המדריך הזה נחוץ רק אם רוצים להפעיל את האתר עם שרת.

> **חשוב לדעת לפני שמתחילים.** בתוכנית החינמית של Render המופע **נרדם** אחרי 15 דקות בלי כניסות, והכניסה הבאה
> מחכה בערך דקה עד שהוא מתעורר. התזכורות לטלפון רצות בתוך השרת, ולכן **כשהמופע ישן הן לא נשלחות**
> (תזכורת שהגיע זמנה בזמן שינה לא תישלח אחר כך). לבדיקות זה בסדר; להשקה צריך מופע שלא נרדם
> (תוכנית בתשלום, או שרת משלכם: [deploy-oracle.md](deploy-oracle.md)).
> תנאי החינם של Render ושל Neon (גבולות, שינה, אחסון) משתנים מדי פעם. בדקו אותם באתרים לפני שמתחילים.

## מה צריך

- כתובת מייל וחשבון GitHub (ל-Render נוח להתחבר איתו).
- כ-30 דקות. לתוכניות החינמיות בדרך כלל לא נדרש כרטיס אשראי (בדקו באתרים, התנאים משתנים), ולתוכנית בתשלום ב-Render כן יידרש.

## 1. פותחים מסד נתונים חינמי ב-Neon

1. נכנסים ל-**neon.com** (או `console.neon.tech`) ולוחצים **Sign up**. אפשר להירשם עם GitHub או עם מייל.
2. אחרי הכניסה לוחצים **Create project** (או **New project**).
3. ממלאים:
   - **Project name:** `lupu-fit`
   - **Postgres version:** 16 או 17 (מה ש-Neon מציע כברירת מחדל מתאים).
   - **Region:** **AWS Europe (Frankfurt)**, כלומר `eu-central-1`. זה אותו אזור (Frankfurt) שבו השרת ב-Render, ולכן הכי מהיר.
4. לוחצים **Create project**. אחרי כמה שניות נפתח לוח הבקרה של הפרויקט.

## 2. מעתיקים את כתובת החיבור (ה-DIRECT!)

1. בלוח הבקרה של הפרויקט לוחצים **Connect** (כפתור בראש המסך).
2. אצל **Connection pooling** מכבים את המתג (הוא צריך להיות **כבוי**). בוחרים Branch `main` ו-Database `neondb` אם נשאלים.
3. מעתיקים את המחרוזת שמתחילה ב-`postgresql://` ומסתיימת ב-`?sslmode=require&channel_binding=require`
   (כפתור **Copy snippet**, או לחיצה על הסיסמה כדי להציג ואז Copy).
4. שומרים אותה זמנית בהערות. היא מכילה סיסמה, אז **לא שולחים אותה לאף אחד ולא מפרסמים אותה**.

> למה Direct? כתובת עם `-pooler` בשמה עוברת דרך שכבת חיבורים של Neon שלא שומרת את הנעילה
> שהשרת צריך כדי ליצור את הטבלאות. אם בטעות הדבקתם כתובת כזו, השרת ירשום בלוג הודעה על כך.

## 3. פותחים חשבון ב-Render

1. נכנסים ל-**render.com** ולוחצים **Get Started** (או Sign up) ובוחרים **GitHub**.
2. מאשרים ל-Render גישה לחשבון GitHub. הכי פשוט לתת גישה ל-repo הזה בלבד (**Only select repositories**).
   אם ה-repo ציבורי אפשר גם בלי לתת גישה: בשלב הבא בוחרים **Public Git Repository** ומדביקים את הכתובת.

## 4. יוצרים את השירות מה-Blueprint

1. ב-Render לוחצים **New +** ואז **Blueprint**.
2. בוחרים את ה-repo (`lupuyuval51-ship-it/-`). Render מציג את הענפים.
3. בשדה **Branch** בוחרים (או כותבים) את הענף: **`claude/optimistic-cori-a3f48u`**.
4. Render קורא את `render.yaml` ומציג שירות אחד בשם `lupu-fit`. נותנים שם ל-Blueprint (למשל `lupu-fit`).
5. ממלאים את המשתנים שה-Blueprint מבקש:
   - **`DATABASE_URL`**: מדביקים את כתובת ה-Direct מ-Neon (שלב 2).
   - **`AI_API_KEY`**: מפתח Gemini למאמן ה-AI ולניתוח תמונות אוכל (`AI_PROVIDER` כבר מוגדר ל-`gemini`). מקבלים אותו בחינם
     ב-[Google AI Studio](https://aistudio.google.com) → **Get API key**. **אפשר להשאיר ריק**: האפליקציה עובדת גם בלי AI
     (מצב "מאמן מובנה"). אפשר להוסיף מפתח אחר כך (שלב 8).
     שימו לב: בגרסה החינמית Google עשויה להשתמש בשיחות לשיפור המוצרים שלה (כולל קריאה על ידי אנשים). האפליקציה לא שולחת
     את השם או המייל, ומציגה למשתמשים הודעה על כך. לפרטיות מלאה: `AI_PROVIDER=anthropic` עם מפתח Claude בתשלום.
   - את `SESSION_SECRET` Render יוצר לבד, ולא צריך לגעת בו.
6. לוחצים **Apply** / **Deploy Blueprint**.

## 5. מחכים לבנייה

1. Render בונה את התמונה מ-`lupifit/Dockerfile`. זה לוקח כמה דקות. אפשר לעקוב: **Dashboard → lupu-fit → Logs**.
2. הבנייה הצליחה כשבלוג מופיעות שורות כמו `applied … migration(s)`, `seeded 119 exercises …` ו-`LUPU-FIT listening on …`,
   ובראש הדף מופיע **Live**.
3. אם מופיעה שגיאה אדומה, ראו "אם משהו לא עובד" בסוף.

## 6. מעתיקים את הכתובת ובודקים

1. בראש הדף של השירות מופיעה הכתובת, בצורה `https://lupu-fit-….onrender.com` (או `https://lupu-fit.onrender.com`).
   **העתיקו אותה**: זו כתובת האפליקציה שלכם.
2. פותחים אותה בדפדפן בטלפון. אמור להופיע מסך הכניסה של LUPU-FIT בעברית.
   (בכניסה הראשונה אחרי תקופה בלי כניסות זה לוקח כדקה: המופע מתעורר.)
3. פותחים `הכתובת-שלכם/api/health`. אמורה להופיע שורה שמכילה `"status":"ok"`.
4. נרשמים עם מייל וסיסמה (לפחות אות אחת וספרה אחת), ועוברים על ההרשמה כדי לוודא שהכול עובד.
5. כשמסיימים לבדוק, אפשר למחוק את משתמש הבדיקה מתוך האפליקציה (הגדרות → מחיקת חשבון).

אין צורך להגדיר כתובת האתר (`APP_URL`): השרת משתמש בכתובת ש-Render נותן לו.

## 7. אפליקציית האנדרואיד

> יש שתי אפליקציות אנדרואיד. האפליקציה של **מצב המכשיר** (`android/`) לא צריכה שרת בכלל: הנתונים נשמרים בטלפון,
> ואין צורך בשום חלק מהמדריך הזה כדי לבנות אותה (ראו [device-mode-he.md](device-mode-he.md) ו-[android.md](android.md)).
> החלק הזה מתאים רק לאפליקציה שפותחת את האתר (`android-twa/`, [android-twa.md](android-twa.md)).

אפליקציית האתר ב-Google Play היא קליפה שפותחת את האתר שלכם במסך מלא, ולכן היא צריכה את כתובת ה-`onrender.com` הקבועה.

1. בונים את האפליקציה עם הכתובת (בלי `https://`):
   `./android-twa/build-aab.sh --host lupu-fit-….onrender.com …`
   (כל השלבים והדרישות ב-[android-twa.md](android-twa.md)).
2. אחרי ההעלאה הראשונה ל-Google Play מעתיקים את טביעת ה-SHA-256 של **App signing key certificate**
   (Play Console → Test and release → App integrity) ומוסיפים אותה ב-Render:
   **Dashboard → lupu-fit → Environment → Add Environment Variable**, שם: `ANDROID_PLAY_CERT_SHA256`, ערך: הטביעה. שומרים.
   Render מפעיל את השירות מחדש לבד.
3. בודקים ש-`https://הכתובת-שלכם/.well-known/assetlinks.json` מציג את החבילה `com.lupufit.app` ואת שתי הטביעות.

> לטלפון עם התוכנית החינמית: כשהמופע ישן, פתיחה ראשונה של האפליקציה תחכה כדקה. זו עוד סיבה להשקה על מופע שלא נרדם.

## 8. הוספת מפתח AI אחר כך

**Dashboard → lupu-fit → Environment**, עורכים את `AI_API_KEY`, מדביקים את המפתח (Gemini מ-aistudio.google.com, או
Claude אם משנים את `AI_PROVIDER` ל-`anthropic`), שומרים. השירות מתחיל מחדש לבד.

## 9. מעבר לתוכנית בתשלום (שרת שלא נרדם)

כשרוצים שהתזכורות לטלפון ירוצו כל הזמן ושלא יהיה זמן המתנה בפתיחה:

1. ב-GitHub פותחים את הקובץ `render.yaml` בענף `claude/optimistic-cori-a3f48u`, לוחצים על העיפרון (**Edit**), ומחליפים
   את השורה `plan: free` ב-`plan: starter`. לוחצים **Commit changes**.
2. ב-Render: **Dashboard → lupu-fit → Settings → Instance Type** ובוחרים את התוכנית הקטנה שאינה חינמית (`Starter`).
   אם Render מציע **Sync Blueprint** אחרי השינוי בקובץ, אפשר לאשר אותו במקום.
3. **בדקו את המחיר העדכני** בדף Pricing של Render לפני שמאשרים. המחיר לא מופיע כאן בכוונה, כי הוא משתנה.

מסד הנתונים נשאר ב-Neon ואין צורך להעביר דבר.

## 10. עדכון גרסה

Render בונה ומעלה גרסה חדשה לבד בכל פעם שמתעדכנים קבצים תחת `lupifit/` בענף שבחרתם
(שינויים בתיקיות `android`, `android-twa`, `docs` ו-`e2e` לא מפעילים בנייה).
אפשר גם להפעיל ידנית: **Dashboard → lupu-fit → Manual Deploy → Deploy latest commit**.

## אם משהו לא עובד

| מה רואים | מה עושים |
|---|---|
| ב-Logs: `DATABASE_URL is required` או שגיאת התחברות למסד | בודקים ב-**Environment** שהערך של `DATABASE_URL` הודבק שלם. כתובת Direct של Neon, בלי `-pooler` בשם השרת. |
| ב-Logs הודעה על `-pooler` | הדבקתם כתובת עם pooling. חוזרים לשלב 2, מכבים **Connection pooling**, מעתיקים שוב ומעדכנים ב-Environment. |
| הדף נטען לאט מאוד בפעם הראשונה | המופע החינמי התעורר מהשינה. זה צפוי; הרענון הבא מהיר. |
| ההתחברות ל-Neon מתעכבת בפעם הראשונה אחרי הפסקה | מסד החינם של Neon "נרדם" כשהוא לא בשימוש ומתעורר תוך רגעים. נסו שוב. |
| הבנייה נכשלה | ב-Logs מחפשים את השורה האדומה הראשונה. אם כתוב `429` או הגבלת קצב של Docker Hub, מנסים **Manual Deploy** שוב אחרי כמה דקות. |
| `assetlinks.json` מחזיר 404 | `ANDROID_APP_PACKAGE` לא הוגדר. ב-`render.yaml` הוא כבר מוגדר ל-`com.lupufit.app`. ודאו שהענף העדכני נפרס. |
